## 说明

- 粗体为 flag 波；新敌人首次出现均不早于第 3 波（1-2 的 twig_husk 首次出现在第 3 波）。
- 脚本解由 `crates/rootguard-app/tests/common/bot.rs` 的机器人录制、`tests/scripts/<id>.ron` 保存，
  `cargo test -p rootguard-app --test scripted_levels` 回放。窗口演示：`cargo run -p rootguard-app -- --autoplay tests/scripts/1-3.ron`。
- “手动用时”需要真人在窗口中试玩，实现者无法代填（见 `docs/progress.md` 待办）。

## 1-4 ～ 1-10 的设计与调整记录

初稿由 `scripts/gen_levels.py` 按预算生成（每波威胁恰为预算，新敌人第 3 波起约占 25%，其余特殊敌人
各分一份，余数用 husk 补齐）。机器人与参数搜索见 `crates/rootguard-app/tests/common/bot.rs` 与
`tests/scripted_levels.rs::record_plan`。

1. **初稿**：中段（第 ⌈W/2⌉ 波）与最后一波各一个 flag，首波 2700、其余 2000、flag 2400 tick。
   机器人在 1-4 起全部失败：5 条车道 × 起始 50 Dew 的经济撑不住中段 flag（1-4 第 4 波威胁 18）。
2. **第一次调整**：取消中段 flag（SPEC 4.5 只要求最后一波为 flag），间隔改为首波 3000 / 其余 2400 /
   flag 3000。1-4 仍失败。
3. **第二次调整**：车道逐步打开（第 1 波只走中路 `Fixed(2)`，第 2 波走 1、3 路，之后分散），
   间隔改为首波 3600 / 其余 2700 / flag 3000。配合机器人改进（安全放置、墙后荆棘垫、地雷 / 炽球 / 咬夹草
   战术），1-4 ～ 1-8 得到脚本解；1-9、1-10 在约 50 组参数 × 多种卡组下全部失败（最好存活到约
   23500 / 24400 tick，即第 8 ～ 9 波）。

预算本身（`ceil(base × k^1.15)`、flag ×2）始终未改。按 AGENT.md 3.5（“无法写出脚本解且已调整波次两次”）
已停止调整 1-9 / 1-10 并向负责人提问；初稿保存在 `tmp/drafts/`（未入库）。
4. **第三次调整（2026-10-14，负责人批准）**：预算不变；1-9 / 1-10 的 husk 余数改为每点威胁生命更低的
   敌人（1-9：跳栏 / 疾行，自第 3 波；1-10：疾行 / 背篓 / 跳栏），波间隔 1-9 为 3600 / 3300 / 3300。
   1-9 得到脚本解（用掉全部 5 个 Hose，难度很高，建议手动试玩后再评估）。
