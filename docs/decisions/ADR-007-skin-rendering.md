# ADR-007：皮肤模式的渲染方式与原创造型约定

- 编号：ADR-007
- 标题：皮肤模式的渲染方式与原创造型约定
- 日期：2026-10-14
- 状态：已接受

## 背景

SPEC 12.1 / 12.3 要求 `SkinMode::Skinned` 以引擎 RON 格式的图集与动画片段绘制角色，“两种模式切换无差异”
是 G5 的首要验收（AGENT 第 10 章）。实现时有两处需要决定：

1. 引擎的现成路径是给实体挂 `Sprite` + `Animator` 组件，由引擎 FixedUpdate 的 `animation_system` 推进、
   `sprite_render_system` 绘制。但对局实体是模拟实体：给它们添加组件会把实体移到另一个 hecs 原型，
   改变后续查询的迭代顺序；为它们另建“影子”实体则会改变后续模拟实体的 id 分配（快照与同 tick 排序都
   以实体 id 为准，SPEC 2.5）。两者都可能让皮肤模式下的模拟结果与占位模式不同。
2. 前任提前编写的 `gen_skins.py`（负责人允许直接使用）中有几处造型与同类型游戏的常见形象较接近，
   AGENT 4.1 / SPEC 1.2 要求“拿不准就按越界处理，换方案”。

## 决策

1. **皮肤只在 Render 阶段绘制**（`rootguard-app/src/skin.rs`）：启动时按 `assets/skins/default/skin.ron`
   清单用引擎 `load_atlas` / `load_clip` 加载（格式与校验完全由引擎负责），每帧在 `draw_battle` 中读取
   模拟组件，按“片段 + 已播放 tick”从 `AnimationClip` 数据算出帧并直接提交 `DrawList::sprite`。
   不添加组件、不创建实体、不使用引擎 `Animator`。
2. **动画状态全部由模拟状态推导，不另存**：循环片段用 `fixed_tick + 实体 id × 7`（错开相位）；
   射手的 attack 用 `Shooter.timer` 已经过的 tick（发射后播放一次）；咬夹草咀嚼时循环 attack；
   块茎雷武装后 armed；敌人按 `Walker.state` 选 walk / eat，护甲破损后选 `bare_` 版。
3. **受伤闪白**：引擎精灵着色是乘法，无法变亮，因此生成脚本为每个敌人帧额外生成 `<帧名>_flash`
   （颜色向白色混合 70%，与占位模式一致）。Chill 与低生命仍用着色。
4. **回退**：皮肤加载失败只 `log::warn!`（SPEC 12.1 皮肤为尽力而为）；单个实体缺少片段时画占位图形。
   卡槽在皮肤模式显示 idle 第 0 帧图标（SPEC 11.2）。
5. **验收测试**（`tests/skin.rs`）：`skin_covers_all_content`（全部防御者 / 敌人 / 弹丸 / Dew 有片段，
   帧数符合 SPEC 12.3，eat 含 `eat_hit`，敌人帧有闪白版）、`skinned_mode_draws_sprites`、
   `skin_switching_keeps_golden_1_4`（对局中每 500 帧切换一次模式，30000 帧后快照与占位模式生成的 golden
   逐字节一致）。
6. **原创造型约定**（`scripts/gen_skins.py` 文件头同步说明）：射手是托着石子的“投石杯”，不画头部侧面的
   圆形开口；树皮墙不画眼睛；块茎雷武装后以裂纹发光表示，不用顶部闪灯；跳栏枯壳用弹簧腿，不画撑杆；
   葫芦壳用干葫芦的黄褐色；Dew 为水滴形。所有角色仍由 ≤ 6 个基本形状组成。

## 后果

- 两种模式的模拟逐字节相同由测试保证；皮肤渲染不需要关心暂停（帧由 `fixed_tick` 决定，暂停时自然静止）。
- 动画事件 `eat_hit` 只作为数据存在（SPEC 12.3 要求的事件帧）；当前没有消费者。若将来需要（如啃食音效
  与动画同步），由呈现层按同样的帧计算判断“进入事件帧”，而不是启用引擎 `Animator`。
- E-3 合入后，精灵已带 `sort_y`（格子中心 y），行图层回退可与形状一起删除。

## 替代方案

- （1）在模拟实体上挂 `Sprite` / `Animator`：可能改变查询顺序，违背“切换无差异”，否决。
- （1）另建呈现实体并映射：改变实体 id 分配，否决。
- （3）闪白用叠加一层半透明白色矩形：会盖住轮廓与背景，观感差，否决。
